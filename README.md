# Aurus — Catalogue

A single, static catalogue site. One name — **Aurus** — over four catalogues:

| # | Catalogue | What it shows | Path |
|---|-----------|---------------|------|
| 01 | **Blinco** | Premium laminates | `/blinco` |
| 02 | **Kudos Handles** | Cabinet, kitchen & wardrobe handles and pulls | `/kudos-handles` |
| 03 | **Kudos Knobs** | Knobs, drop pulls and folding handles | `/kudos-knobs` |
| 04 | **Ciscon** | Acrylic laminates | `/ciscon` |

No frameworks, no build step. Hand-written HTML, CSS (design tokens) and vanilla JS.
Fonts are self-hosted (no runtime CDN). It deploys to Vercel as **one** project.

---

## Preview locally

It's plain static files, but the pages use absolute links (`/blinco`, etc.), so serve
from the project root rather than opening files directly.

```bash
cd aurus-catalogue

# Recommended — a tiny threaded server that mirrors Vercel's clean URLs
python tools/serve.py 5173
#   → open http://localhost:5173

# …or Node, if you prefer
npx serve .
```

> **Always preview over HTTP — don't double-click `index.html`.** Opening it from disk
> (`file://`) blocks the self-hosted fonts (CORS) and breaks the `/blinco`-style links.
> Also avoid plain `python -m http.server`: it's single-threaded and stalls when a page
> requests many images at once. `tools/serve.py` is threaded and serves `.webp` correctly.

## Where the images live, and how to update each catalogue

Every catalogue reads its images from its own folder and a small, editable list at the
**bottom of that catalogue's `index.html`**.

```
assets/brands/
├── blinco/          ← drop Blinco images here
├── kudos-handles/   ← drop Kudos Handles images here
├── kudos-knobs/     ← drop Kudos Knobs images here
└── ciscon/          ← drop Ciscon images here
```

> ### ⚡ Performance: run the image optimiser
> The raw catalogue scans are huge (some are 9000+ px wide, ~360 MB total). Loading those
> directly makes the page crawl. So the site loads small **WebP** derivatives instead:
> a tiny one for the grid/filmstrip and a screen-sized one for the viewer, both generated by
> `tools/optimize-images.py`. The originals stay in place and are used only as a fallback.
>
> **After you add or replace any images, run:**
> ```bash
> python tools/optimize-images.py    # needs Pillow:  pip install Pillow
> ```
> It writes `assets/brands/<brand>/thumbs/*.webp` and `.../view/*.webp` (re-running only
> processes new/changed files). This is the one optional step — the site still works without
> it (it falls back to the originals), it just won't be as fast. **Commit the generated
> `thumbs/` and `view/` folders so they deploy with the site.**

### To replace or add images for a catalogue

1. **Drop the image files** into the matching `assets/brands/<brand>/` folder.
2. **Run `python tools/optimize-images.py`** to (re)generate the WebP derivatives.
3. **Open that brand's page** (`<brand>/index.html`) and find the `window.AURUS_CATALOGUE`
   block near the bottom. Edit the `pages` list so it names your files **in display order**:

   ```js
   window.AURUS_CATALOGUE = {
     brand: "Blinco",
     descriptor: "Premium laminates",
     base: "../assets/brands/blinco/",
     pages: [
       "blinco-01.jpg",
       "blinco-02.jpg",
       // …add / reorder / rename to match your files
     ]
   };
   ```

That's it — the grid and the full-screen viewer build themselves from that list.
Filenames may contain spaces or punctuation (Ciscon's already do); they're URL-encoded
for you automatically. The page counter in each hero (`65 pages`, etc.) is plain text —
update it if your page count changes.

**Note on Kudos Handles:** because it has 100 sequentially-named pages
(`kudos-handles-001.jpg … kudos-handles-100.jpg`), its page is set up to generate that
list with a tiny loop instead of 100 literal lines. If your filenames differ, replace
the `buildPages()` call with a literal `pages: [ ... ]` array like the other catalogues.

### Current state
The four folders are **pre-filled with the real catalogue images** and every manifest is
already wired up, so the site works as-is. Re-dropping files just means updating the list.

## What's shared vs. per-brand

Everything is shared except a single accent colour:

```
assets/shared/
├── tokens.css     design tokens — colour, type, spacing, motion (+ per-brand accent)
├── base.css       reset, typography, shell, reveal-on-scroll, the full-screen viewer
├── catalogue.js   builds the grid + viewer from each page's manifest
├── shell.js       reveals, sticky bar, catalogue switcher, soft page transitions
└── fonts/         Schibsted Grotesk (display) + Hanken Grotesk (text), self-hosted
```

The per-brand accent is set by `<body data-brand="…">` and defined in `tokens.css`:

```css
body[data-brand="blinco"]        { --accent: #a87f4c; } /* brass / oak  */
body[data-brand="kudos-handles"] { --accent: #5d6f78; } /* slate steel  */
body[data-brand="kudos-knobs"]   { --accent: #8a6a4d; } /* bronze       */
body[data-brand="ciscon"]        { --accent: #4d7a73; } /* sage acrylic */
```

Change a hex there to retint a catalogue. Nothing else differs between brand pages.

## Deploy to Vercel (one project, one link)

`vercel.json` is already set with `{ "cleanUrls": true, "trailingSlash": false }` so the
URLs are `/blinco` (no `.html`, no trailing slash).

**Option A — Git (recommended)**
1. Push this `aurus-catalogue/` folder to a Git repo (GitHub/GitLab/Bitbucket).
2. In Vercel → **Add New… → Project** → import the repo.
3. Framework preset: **Other**. Build command: *none*. Output directory: **`.`**
   (If the repo root *is* this folder, leave defaults — there's no build step.)
4. **Deploy.** You get one URL, e.g. `https://aurus.vercel.app`, with all four
   catalogues under it.

**Option B — Vercel CLI**
```bash
npm i -g vercel
cd aurus-catalogue
vercel          # preview deploy — follow the prompts
vercel --prod   # promote to your production link
```

Re-deploy any time you add images or edit a manifest (push to Git, or run `vercel --prod`).

## Accessibility & performance notes
- Semantic HTML, descriptive `alt` on every page image, visible focus states, full keyboard
  support in the viewer (←/→, Home/End, Esc, Tab focus-trap) and a focus trap while open.
- Respects `prefers-reduced-motion` — reveals, zooms and page transitions all stand down.
- Images are `loading="lazy"` with reserved aspect-ratio boxes (no layout shift); the viewer
  preloads only the neighbouring pages.
- Single quiet palette, one display + one text typeface, all assets local — fast first paint.
